Section 01 — 通识精读（今日主线）
FOUNDATIONSTraining Language Models to Follow Instructions with Human Feedback（InstructGPT）
Ouyang et al. · OpenAI · 2022-03-04 · 后发表于 NeurIPS 2022 · arXiv:2203.02155 · 通识计划第 6/20 篇
为什么是分水岭：GPT-3 证明了「大就是强」，但它是个补全器——你问「怎么煎蛋」，它可能接着写「怎么做松饼」。InstructGPT 用人类反馈强化学习（RLHF）把「会续写」变成「听指令」，摘要原文给出最锋利的一句话：1.3B 参数的 InstructGPT 输出被人类评估者偏好于 175B 的 GPT-3——参数少 100 倍。这一篇是 ChatGPT 的直系技术前身，SFT → 奖励模型 → 强化学习三阶段成为此后所有对话模型（包括你每天在用的）的出厂模板。它回答的问题到今天仍是主线：能力不够时，先问「目标对没对准」。

核心思想（讲给 12 岁）：GPT-3 像一个读遍了图书馆、但只会「接着你的话往下说」的实习生。InstructGPT 是一套三步教学法：第一步做示范（SFT）——老员工先演示标准做法；第二步学打分（RM）——不要求人类批改每一份作业，而是从人类的排名比较里训练出一个「助教评分器」，让它替人打分；第三步刷练习（PPO）——实习生对着助教的分数反复练习，但有一条纪律：不许为了高分变成另一个人。核心洞察：人类的时间是稀缺的，把「人类的品味」蒸馏成一个可无限次查询的评分器，规模化问题才解决。

原理机制（A→B→C）：A · SFT 监督微调——标注员对指令写出理想回答（约 1.3 万条训练提示），把 GPT-3 先拉到「会好好回答」的起点；B · RM 奖励模型——让模型对同一指令生成多个回答，标注员只做排名比较（约 3.3 万条），用排序损失训练出打分模型——比较比绝对打分更可靠；C · PPO 强化学习——模型生成回答、RM 打分当奖励，同时加 KL 惩罚：输出偏离 SFT 初始模型太远就罚分。KL 约束是灵魂——没有它，模型会钻奖励模型的空子（reward hacking）；有它，高分必须来自「好好回答」而不是「变成马屁精」。

与近期进展的联系：本周速递六篇 RSI 把「反馈源」从人换成了模型与环境——LM2LM 用 LM 自动改进 LM（2610.23344），CoEvo-RSI 让 harness 自进化后只要求模型「跟跑」（2610.25078）；而 Into the Unknown（2610.19159）的 0/135 审计结果恰好说明人类这一环目前仍不可省。本周新线索：InstructGPT 作者列表里的 Diogo Almeida 创办了 TypeSafe AI（见 05 深潜）。回看通识线：Chinchilla 说算力要分给参数与数据，InstructGPT 补上第三根轴——对齐目标的收益可以超过 100 倍参数差距。

今日怎么读（15 分钟路线）：先读摘要（1.3B vs 175B 那句是全文题眼）→ 直跳方法节（Section 3，三阶段流程与数据量：SFT 13k / RM 33k / PPO 31k 提示）→ 结果节（Section 4）看 labeler 偏好图与「公开 NLP 基准上性能反而下降」的对齐税讨论 → 最后读 Limitations 段。推导与超参附录全跳过。

延伸阅读：论文评估设计（人类评估 > 基准分数）是本周 Into the Unknown 审计思想的雏形；下一课预告：通识 #7 DPO《Direct Preference Optimization》（arXiv:2305.18290，NeurIPS 2023）——把 RLHF 三阶段坍缩成一次监督训练，正好接住今天的三步教学法。
INSIGHT BY AI能力的天花板未必在参数，在目标——1.3B 赢 175B 的本质是「练对了题」。

★ 103,868 · 本周 +9,545 · TypeScript · MIT
它是干嘛的：把 Codex、Claude Code、OpenCode、Pi 并排跑起来的「AI 编排器」——每个 agent 独立 git worktree，一处追踪。
展开详细分析

解决什么问题：多 agent 并行时窗口爆炸、成果散落——你需要在五个终端间人肉搬运上下文。

怎么上手：onorca.dev/download 一键装桌面端（macOS/Windows/Linux），移动端有 iOS App 与 Android APK。

为什么现在火：多 agent 协作从演示走向日常，「fleet of agents」的基础设施位被桌面应用占住。

与你的方向的连接：harness 主题（04 深度）的消费者端形态——编排层就是人肉 harness 的产品化。

INSIGHT BY AI单 agent 的尽头是编队——「比较五份作业再 merge 胜者」把多样性变成了工程手段。

akitaonrails/ai-memory
★ 13,041 · 本周 +3,449 · Rust · MIT
它是干嘛的：AI coding agent 的跨 harness 长期记忆——Claude Code 干到一半退出，同目录打开 Codex 无需重新解释架构与失败路径，直接接续。
展开详细分析

解决什么问题：各家 agent 的记忆锁在自家机器与自家格式里，换工具 / 换机器 / 交接队友即失忆。

核心机制：20+ harness 喂同一共享记忆；typed handoff 协议（有 owner、恰好被认领一次）；记忆的真源是 git-backed 的普通 markdown wiki——可 grep、可进 Obsidian、可手改，数据库只是可重建的派生索引，没有向量库；捕获 / 搜索 / 交接零 LLM 调用；记忆按访问加权衰减（常用的忘得慢），冷 episodic 笔记压缩成持久事实（文件路径 / 错误码 / 决策），近重复合并、矛盾标记，永不硬删（git 版本链可恢复）。

怎么上手：Rust 单二进制自托管 server，ai-memory run codex 即以共享工作流启动。

为什么现在火：与本周 MemT / Deep Fusion Memory（03 速递）同题异构——学界在把记忆压进权重，社区在把记忆摊成文件。

与你的方向的连接：「记忆 = 可 grep 的 markdown 本体」正是本体论-工程线的民间答案，与你自己的 concepts-index 同构。

INSIGHT BY AI最可靠的 agent 记忆不是更大的向量库，是一份你能直接打开的 wiki——可审计性优先。

Section 04 — 技术方向深度
harness 先于权重——自改进的「指挥权」上移
核心判断：自改进的研究前沿正在发生一次对象迁移——从「改模型」到「先改 harness、模型跟跑」。这不是工程权宜，而是因为 harness 层的改进循环比权重层快一个数量级；但它同时撞上了本周最冷的数据：agent 自报的科研产出，135 篇里 0 篇通过完整审计。

① 为什么是现在：上期（NO.007）四篇 RSI 改的都是模型本身（Terminal-RSI 的指标自生成、Athanor 的学生超越教师）。本周风向明显变化：CoEvo-RSI 直接把问题写成标题——「当 harness 进化时，哪些模型该跟进」；微软的 Harness-Policy Optimization 首次把 harness 纳入训练闭环；Epi 把 harness 做成持久化基础设施（记忆跨任务累积）。与此同时热榜上 ruflo 自称 meta-harness、orca 卖多 agent 编排、K-Dense 把科研拆成 177 个 harness 技能——论文与产品在同一周指向了同一个层。

② 大白话 + 类比：模型是司机，harness 是整辆车——导航、仪表盘、维修手册、备用轮胎。改进司机要回驾校重训（贵、慢、一次改一点）；改装车只要拧螺丝（便宜、快、可回滚）。本周论文的集体结论：先改装车，司机只需跟班培训。CoEvo-RSI 的实验里，harness 进化之后模型只做一次 SFT（用自身拒绝采样筛出的好轨迹）就能追上大它几倍的对手——因为瓶颈从来不全在司机。

③ 原理机制（A→B→C，以 CoEvo-RSI 与 HPO 为例）：A · harness 层变异——用更强模型（或人类反馈）对现有 harness 提出修改提案：工具集、提示词结构、验证规则、记忆组织；B · 筛选与留痕——跑基准，只有通过的提案保留（HPO 里这是显式的联合优化目标）；C · 模型跟跑——把 harness 筛选出的「好行程」轨迹做成 SFT 数据回灌模型，让权重吸收 harness 层的成果，下一轮 harness 在更强的模型上继续变异。这就是上周深度（自改进的样本效率三件套）的延伸：harness 把「评估便宜」做到了极致——改动是文本级的，失败成本近乎零，所以循环能转得飞快。

④ 证据与边界：正方是 Epi——不刷基准，直接产出 120 项可查证的数学 / 物理纪录（Feigenbaum 吸引子维数区间收窄 360 万倍），且在 FrontierOR 上比 Codex 高 5.4% 只花 64% 成本；反方是 Into the Unknown——9 个前沿 agent 写的 135 篇「后续论文」，0 篇满足全部录用条件，114 篇过不了诚信检查（编造实验、数字对不上原始记录）。两条合起来的教训：harness 能让产出速度起飞，但「证据链完整性」必须长在 harness 里，而不是靠模型自觉。评估便宜的三件套里，第三件（失败便宜）不该滑成「造假也便宜」。

⑤ 怎么用到你自己的工作流：搭任何 agent 流程时，把「可验证产物」写进 harness——测试、基准断言、原始记录留痕、像 ai-memory 那样 git-backed 的轨迹文件；改进顺序永远是先拧 harness 的螺丝（工具 / 提示词 / 缓存 / 记忆），确认瓶颈在权重再动训练。本周 Cache Engineering（03 #10）连缓存策略都能自改进——说明 harness 层的空间远没见顶。

⑥ 延伸阅读：CoEvo-RSI（2610.25078）与 HPO（2610.22791）对读，一文一工业；Into the Unknown（2610.19159）读它的评估协议设计而非结论；回看今日通识——InstructGPT 的 RLHF 是这个闭环的祖先：反馈驱动更新从未变过，变的只是反馈源（人 → 环境 → 自身）与改进对象（权重 → harness）。
核心判断改进循环的快慢由「改一次的成本」决定——harness 把成本打到文本级，指挥权自然上移；但证据链也得长在 harness 里，否则只是更快地产出不可信的东西。

答案：C。1.3B 赢 175B 说明的是「对齐目标」的收益：GPT-3 的能力没有被对准到「听指令」上，InstructGPT 用 RLHF 对准了它。A 是常见误解（架构未变，同为 GPT 系列）；B 与事实相反（GPT-3 预训练数据更多）；D 无中生有——RLHF 不改变参数量。

Q2 RLHF 为什么要先训练一个奖励模型（RM），而不是让人类直接给 PPO 训练的每一步打分？提示：01 通识「原理机制」。干扰项 A 的陷阱：省钱是结果，不是机制。

答案：B。机制核心：人类时间稀缺 → 只能给有限次比较 → RM 把偏好蒸馏成可规模化查询的打分函数。A 把结果当机制；C 不成立（RM 是 PPO 的前置组件，不是替代）；D 无中生有。

Q3（跨期连接）今日通识的 RLHF 与本周速递的自改进（LM2LM、CoEvo-RSI），共享的骨架是什么？提示：01「与近期进展的联系」+ 03 速递 #15 / #6。

答案：A。RLHF 与 RSI 共享「反馈 → 更新」闭环，差别在反馈源：InstructGPT 的反馈来自人类排名，LM2LM / CoEvo-RSI 的反馈来自模型或环境的自动信号。B 错（自改进靠评估反馈驱动）；C 是表面印象，深度 ④ 已说明两者是同一闭环的不同反馈源；D 错（两者都更新参数，改上下文的是外挂式路线如 Memento 3）。

Q4（跨期连接 · 上期 ResNet ↔ 本期 PAR）PAR 用 progress-aligned recurrence 把状态跟踪外推到 16 倍训练长度，它与上期通识 ResNet 的残差块共享什么数学骨架？提示：NO.007 通识 01「原理机制」+ 本期 03 #17。

答案：D。ResNet 让层学 F(x) 而非完整映射，恒等映射保底；PAR 让每步只学「进度增量」并用 norm anchoring 锚定。两者都是「学残差比学全量容易」——学不动的部分由恒等路径兜底，所以深了不退化、长了能外推。A 与 PAR 相反（0.5B 小模型外推）；B、C 均与两篇论文事实不符。
